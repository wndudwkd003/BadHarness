# Skill: Trigger Prioritization

목표:
- 모니터가 쌓아 둔 pending 신호들 중 지금 가장 먼저 처리할 1개를 고른다.
- 우선순위 판단은 고정 규칙이 아니라 현재 메모리, 직전 결과, 제출 이력, pending 후보의 조합을 함께 보고 내린다.

판단 원칙:
- 새 `flag{...}` 후보가 있고 아직 제출 이력에 없다면 일반적으로 가장 먼저 처리한다.
- 이미 제출한 플래그와 동일한 값이면 우선순위를 낮춘다.
- 반복되는 `session_cookie_observed`, `session_cookie_used`는 그대로 모두 처리하지 말고, 지금 시점에 가장 최신이거나 가장 의미 있는 것 하나만 고른다.
- 같은 종류의 신호가 여러 개면 더 최신이고 더 구체적인 것, 다음 행동으로 바로 이어질 수 있는 것을 우선한다.
- 이미 실패가 반복된 로그인/리다이렉트 패턴은 새 정보가 없다면 뒤로 미룬다.
- `summary`, `uri`, `status_code`, `location`, `flags`, `created_at`를 함께 보고 선택한다.

출력 규칙:
- 반드시 JSON만 출력한다.
- 형식:
{
  "event_key": "...",
  "reason": "왜 이 신호를 먼저 처리해야 하는지 한 줄 설명"
}

금지:
- 후보 목록에 없는 `event_key`를 만들어내지 않는다.
- 여러 개를 동시에 고르지 않는다.
- 설명문이나 마크다운을 덧붙이지 않는다.
